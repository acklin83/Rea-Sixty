# REAPER will not start after updating to v0.5.0 on Windows

**This affects Windows only.** macOS and Linux are not affected and need no action.

v0.5.0 has a bug that crashes REAPER while the Rea-Sixty extension loads. REAPER
never opens, so you cannot reach ReaPack to update, and you cannot uninstall the
extension from inside REAPER. You have to move one file by hand. It takes about
thirty seconds and you do not need to reinstall anything.

Sorry about this one. It got through because our automated builds compile the
Windows version but nothing starts it.

## Step 1: get REAPER running again

1. Press **Windows key + R**.
2. Paste this and press Enter:
   ```
   %APPDATA%\REAPER\UserPlugins
   ```
3. Find **`reaper_rea-sixty.dll`**.
4. Rename it to **`reaper_rea-sixty.dll.OFF`**.

REAPER starts again now. It starts without Rea-Sixty, so your surface will not
respond yet. Step 2 fixes that.

If you use a **portable REAPER install**, the folder is `UserPlugins` next to
`reaper.exe` instead, wherever you put REAPER.

If Windows hides the `.dll` part of the name, turn on **View, Show, File name
extensions** in Explorer first, otherwise you will end up with a file still
called `reaper_rea-sixty.dll`.

## Step 2: get Rea-Sixty back

Pick whichever you prefer. Both end up in the same place.

### Through ReaPack, if you already have it

1. Start REAPER.
2. **Extensions, ReaPack, Synchronize packages**.
3. Restart REAPER.
4. Go back to the `UserPlugins` folder and delete the `reaper_rea-sixty.dll.OFF`
   file you made in step 1. It does nothing where it is, it is just clutter.

### By hand, if you would rather not wait

1. Download `reaper_rea-sixty.dll` from the
   [latest release](https://github.com/acklin83/Rea-Sixty/releases/latest).
2. Put it in the same `UserPlugins` folder, replacing the old one.
3. Delete `reaper_rea-sixty.dll.OFF`.
4. Start REAPER.

## How to tell you have a fixed build

Open the Rea-Sixty Settings window: press the **360°** key on the surface, or run
the REAPER action **Rea-Sixty: Open / Close Rea-Sixty Settings** from the Actions
list. Go to the **About** tab and read the line **Version**.

Anything **v0.5.1 or newer** has the fix. If it still says v0.5.0, ReaPack has
not picked up the new version yet. Use **Synchronize packages** again, or install
by hand as above.

## Was it really this, or something else?

If REAPER still will not start after step 1, then Rea-Sixty was not your problem
and something else is wrong. Put the file back and ask on the forum thread.

If you want to confirm it was this bug before you change anything, open

```
%TEMP%\rea_sixty_init.log
```

in Notepad and look at the last lines. This bug ends the file at
`bindings:file read OK, entering parse/upgrade` with no line after it.

## What actually went wrong

The extension asks Windows for more working memory at startup than Windows gives
a program's main thread, so Windows stops the process. The amount grew past the
limit in v0.5.0 because of new UF1 features, and the crash happens before any of
our own error handling runs, which is why REAPER dies without a message.

macOS and Linux give a program roughly eight times more of this memory, so the
same build runs fine there. That is also why it was not caught before release.
The build now refuses to compile if any function gets near the limit.
